# Pre-registered: pairwise rank loss instead of BCE

Registered 2026-08-27, before the run. Fold 0, DINOv2-S.

## Motivation is a MEASURED pathology, not "the metric is AUC"
BCE with a soft target t is optimised by sigma(z) -> t, so it spends capacity matching
MAGNITUDES; AUC ignores magnitudes entirely. That mismatch already cost us a result:

    public labels, CONTINUOUS ordering info vs gold58   0.878  (+0.069 over ours)
    public labels, thresholded at 0.5                   0.782  (identical to ours)
    model trained on them, away_gain                   -0.0030  WORSE

The extra ordering information was real and BCE turned it into a calibration target.
`pairwise_rank_loss` uses the grading as PAIR WEIGHT (y_i - y_j) and discards the absolute
values -- the smooth form of the `soft_auc` metric already in loop.py.

## The batch-size change (CORRECTED before running -- it IS a confound)
Pairwise losses need pairs, so the treatment runs at `--batch-size 16 --accum 1`.
I first claimed this gives gradients identical to the baseline's 8 x 2 because DINOv2 has no
BatchNorm. **That is wrong.** `masked_bce` normalises by each MICRO-BATCH's own `w.sum()`:

    return (l * w).sum() / w.sum().clamp_min(1.0)

so 8 x 2 averages two ratios while 16 x 1 takes one pooled ratio, and label coverage (62.8%)
varies per study. No BatchNorm makes the FORWARD pass identical; it does not make the loss
normalisation identical. Second-order -- and second-order is the size of the effect we are
testing, so it is controlled, not argued away.

**Third run added: BCE at 16 x 1.** That is the correct control for the treatment; the
original 8 x 2 baseline is kept only for continuity with every historical run.

## Design -- three runs, fold 0
    historical  f0_..._slot__fine_fine        T1 0.8661 / T1hq 0.8668 / T1s 0.8688  (8 x 2)
    CONTROL     --loss bce  --batch-size 16 --accum 1
    treatment   --loss rank --batch-size 16 --accum 1
    variant     --loss both --batch-size 16 --accum 1 --rank-w 1.0
Everything else identical: slot cache, policy fused, folds, seed 0, 25 epochs, lr 3e-4,
encoder_lr_mult 0.027, mixup none, fine_attn.

## Decision rule
PROMOTE if **T1hq >= CONTROL(bce @16x1) + 0.005**. The bar is set against the 16x1 control,
NOT the 0.8668 historical figure, because the batch change is not neutral (above).
If `rank` wins and `both` wins by more, the BCE term still contributes and `both` ships.

Unlike the label-policy experiment, **changing the loss does NOT change the ruler** -- T1,
T1hq and T1s are all AUCs against the same fixed targets, so all three are directly
comparable across losses. This experiment is cleanly measurable in a way that one was not.

## Expect and ignore
`val_bce` will be WORSE under `--loss rank` (gate: 0.6227 vs 0.5672 for BCE). A scale-free
loss leaves calibration arbitrary. That is correct behaviour, not a regression, and AUC does
not care. Do NOT use val_bce to compare across losses. `history.csv`'s `loss` column also
changes meaning with `--loss` and is not comparable either.

## Also test if it wins
50/50 rank blend with the BCE-trained model. Two losses on identical pixels and labels is a
diversity axis we have never measured, and it is the only remaining one that does not cost a
second encoder at inference.

---
## RESULT (2026-08-28) — BOTH PROMOTE; `both` is the one to ship

                          T1      T1hq     T1s   val_bce
    historical bce 8x2  0.8661  0.8668  0.8688   0.4020
    CONTROL bce 16x1    0.8700  0.8668  0.8706   0.3990
    rank      16x1      0.8664  0.8849  0.8665   0.5252
    both      16x1      0.8722  0.8826  0.8735   0.3949

Gate (T1hq >= 0.8718): rank +0.0181 PROMOTE, both +0.0158 PROMOTE.
Batch confound: +0.0000 on T1hq, +0.0039 on T1 -- the control was worth running.

**Mechanism confirmed, and it cuts both ways: corr(label_q, rank's per-label gain) = +0.649.**
    label_q >= 0.85 (n=6)   rank +0.0181   both +0.0158
    label_q <  0.85 (n=6)   rank -0.0254   both -0.0114
A pairwise loss commits to EVERY ordering in the target. Where the ordering is signal it gains
(Lateral Meniscus 0.7533 -> 0.8175, +0.064); where it is noise it faithfully learns the noise
(Synovitis 0.676 label_q -> -0.0957). BCE was accidentally protecting us there. `both` keeps
87% of the gain and halves the damage -- the BCE term regularises against noise-ordering.

SHIP `both`: best T1, best T1s, best val_bce, net positive on all twelve, blend gain with the
BCE model +0.0053 (P=1.00, rho 0.934). CAVEAT: one fold, and fold-to-fold SD is 0.0146.

## Two follow-ups launched immediately
1. `both` on fold 1 -- replication. Bar: T1hq >= fold-1 bce control + 0.005.
2. `both` + `--policy public` on fold 0 -- THE REOPENING. The public labels carry +0.069 more
   ORDERING information (continuous gold58 0.878 vs 0.809) and were rejected because BCE turned
   it into a calibration target. A loss that reads ordering and discards magnitude is exactly
   what makes that information usable. Bar: T1hq >= `both`+fused's 0.8826 + 0.005 = 0.8876,
   scored on the FIXED fused ruler (T1/T1hq across policies is otherwise incomparable).
